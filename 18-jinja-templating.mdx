**Jinja2** is used to insert variables into files dynamically.

Instead of hardcoding configs → you generate them.

## Why use Jinja2?
- ❌ Static files
- ❌ Manual updates
- ❌ Not reusable
👉 With Jinja2
- ✅ Dynamic templates
- ✅ Reusable configs
- ✅ Easy maintenance

Example:

This is a Jinja2 template for an nginx configuration file (nginx.conf.j2):

```bash
server {
    listen 80;
    server_name {{ domain_name }};

    location / {
        proxy_pass http://{{ backend_ip }}:{{ backend_port }};
    }
}
```

Playbook to use this template:

```yaml
- hosts: web
  vars:
    domain_name: example.com
    backend_ip: 10.0.0.5
    backend_port: 8080

  tasks:
    - name: Deploy nginx config
      template:
        src: nginx.conf.j2
        dest: /etc/nginx/nginx.conf
```

Output:

```bash
server {
    listen 80;
    server_name example.com;

    location / {
        proxy_pass http://10.0.0.5:8080;
    }
}
```

## Real Use:
- Config files (nginx, apache)

- Environment-based configs

# Ansible Jinja2 Template Example for Multiple Environments

## Project Structure

```text
project/
├── inventory
├── playbook.yml
├── templates/
│   └── nginx.conf.j2
├── group_vars/
│   ├── dev.yml
│   ├── test.yml
│   └── prod.yml
```

---

# 1. Jinja2 Template

## File: `templates/nginx.conf.j2`

```nginx
server {
    listen 80;

    server_name {{ domain_name }};

    location / {
        proxy_pass http://{{ backend_ip }}:{{ backend_port }};
    }
}
```

---

# 2. Inventory File

## File: `inventory`

```ini
[dev]
dev-server ansible_host=192.168.1.10

[test]
test-server ansible_host=192.168.1.20

[prod]
prod-server ansible_host=192.168.1.30
```

---

# 3. Dev Variables

## File: `group_vars/dev.yml`

```yaml
domain_name: dev.example.com
backend_ip: 10.0.0.5
backend_port: 8080
```

---

# 4. Test Variables

## File: `group_vars/test.yml`

```yaml
domain_name: test.example.com
backend_ip: 10.0.1.5
backend_port: 8080
```

---

# 5. Prod Variables

## File: `group_vars/prod.yml`

```yaml
domain_name: prod.example.com
backend_ip: 10.0.2.5
backend_port: 8080
```

---

# 6. Playbook

## File: `playbook.yml`

```yaml
- hosts: all
  become: yes

  tasks:
    - name: Deploy nginx config
      template:
        src: templates/nginx.conf.j2
        dest: /etc/nginx/nginx.conf

      notify:
        - Restart nginx

  handlers:
    - name: Restart nginx
      service:
        name: nginx
        state: restarted
```

---

# How It Works

When you run:

```bash
ansible-playbook -i inventory playbook.yml
```

Ansible:

1. Detects the host group (`dev`, `test`, `prod`)
2. Loads variables from matching `group_vars`
3. Replaces Jinja2 variables in template
4. Generates final config file
5. Copies config to target server
6. Restarts nginx if file changed

# Interview Answer

> In Ansible, Jinja2 templates are used to create dynamic configuration files.  
> Variables are stored separately for different environments like dev, test, and prod.  
> During playbook execution, Ansible replaces template variables with actual environment values and generates the final configuration automatically.

# Problems Without Jinja2

| Problem | Explanation |
|---|---|
| Duplicate files | Same config repeated multiple times |
| Hard maintenance | Need to edit every file manually |
| Error-prone | Easy to forget updating one environment |
| Poor scalability | Difficult with many environments |
| More code | Larger playbooks and configs |
